## ADR-001 — `claude-review.yml` alignment with `anthropics/claude-code-action@v1` (Step 00)
- **Context:** Step 00 requires verifying all inputs and flags in Appendix B (`.github/workflows/claude-review.yml`) against Anthropic's official `anthropics/claude-code-action@v1` documentation before finalizing the workflow.
- **Decision:** Keep the `pull_request` trigger (`opened`, `synchronize`, `ready_for_review`), concurrency group, fork/draft guard, `actions/checkout@v4` (`fetch-depth: 0`), `--max-turns 10`, and `--max-budget-usd 2`, and add:
  1. `id-token: write` and `issues: write` under `permissions:` (required for Claude GitHub App OIDC authentication and posting PR comments).
  2. `--allowedTools "Read,Grep,Glob,Bash(gh pr comment:*),Bash(gh pr diff:*),Bash(gh pr view:*),Bash(git diff:*),Bash(git log:*),Bash(git status:*)"` in `claude_args`, because in `anthropics/claude-code-action@v1` plain-text `prompt` mode defaults to no granted tools unless explicitly allowlisted.
  3. Explicit `REPO: ${{ github.repository }}` and `PR NUMBER: ${{ github.event.pull_request.number }}` context in `prompt` with explicit instruction to post via `gh pr comment`.
- **Alternatives:** Use Appendix B verbatim without `id-token: write` or `--allowedTools`.
- **Reason:** Without `id-token: write`, the Claude GitHub App OIDC flow fails; without `--allowedTools` and PR context, Claude cannot read repository files, inspect diffs, or post the review comment in `prompt` mode.

## ADR-002 — Private repository branch protection on GitHub Free (Step 00)
- **Context:** Step 00 requires enabling branch protection on `main` (require pull request, require owner approval, block direct pushes) and verifying that Antigravity cannot push to `main`.
- **Decision:** Keep the repository private (per Section 0 Rule 12), refrain from making any direct push to `main`, install a local Git `pre-push` hook inside `.git/hooks/pre-push` blocking pushes to `main`, and record the GitHub API finding (`403: Upgrade to GitHub Pro or make this repository public to enable this feature`) in the Step 00 report so the owner can choose either to upgrade to GitHub Pro and enable server-side protection or approve this documented deviation.
- **Alternatives:**
  1. Upgrade the repository owner's account to GitHub Pro (paid plan) and enable branch protection / Rulesets on `main`.
  2. Make the repository public (rejected — violates Section 0 Rule 12).
- **Reason:** Branch protection and Rulesets on private repositories are unavailable on GitHub Free (`protected: false`, `403` on rules endpoint). A local `pre-push` hook prevents accidental pushes from this workstation without violating repository privacy or making unauthorized paid-account changes.

## ADR-007 — Step 01 Windows dev environment, ports, and startup launcher (Step 01)
- **Context:** Step 01 requires a reproducible Windows dev environment with `scripts/start.bat` opening a placeholder UI and `/api/health` returning `OK`. Windows `timeout.exe` fails under non-interactive stdin redirection, and PowerShell `ExecutionPolicy` blocks `npm.ps1` unless `npm.cmd` is invoked.
- **Decision:** Run FastAPI (`uvicorn`) on `127.0.0.1:8000` and Vite React/TypeScript on `127.0.0.1:5173` (using one consistent loopback host `127.0.0.1`, with `vite.config.ts` reading `BACKEND_HOST`/`BACKEND_PORT`/`FRONTEND_HOST`/`FRONTEND_PORT` from repo-root `.env` and `process.env`), invoke `npm.cmd` in `scripts/start.bat`, use `scripts/wait_for_servers.py` instead of `timeout.exe`, resolve blank or relative `WORKSPACES_DIR` against `REPO_ROOT` in `Settings` (removing `DATABASE_URL` from `.env.example` until Step 02), and pin exact tested Python versions (`fastapi==0.164.0`, `uvicorn[standard]==0.54.0`, `pydantic-settings==2.16.3`, `pytest==8.4.2`, `httpx2==2.16.2`) in `backend/requirements.txt`.
- **Alternatives:** Use `timeout.exe` / fixed `sleep` in `.bat`, hardcode Vite proxy port, or rely on `httpx` fallback despite Starlette 1.10.0 deprecation warning.
- **Reason:** Polling real HTTP readiness avoids race conditions, env-driven proxy/host config prevents drift when ports change, and verified `httpx2` keeps `TestClient` warning-free and reproducible.


## ADR-008 — Step 02 Database schema, Alembic migrations, and Arabic workspace naming (Step 02)
- **Context:** Step 02 requires an 11-table database schema (`projects`, `files`, `file_versions`, `tasks`, `task_steps`, `deliverables`, `research_sources`, `issues`, `calculations`, `settings`, `audit_log`), Alembic migrations targeting SQLite initially and PostgreSQL via config later, auto-creation of 12 numbered folders per project, and reliable Windows NTFS handling for Arabic project names across app restarts.
- **Decision:** Use synchronous SQLAlchemy (`2.1.9`) + Alembic (`1.20.1`) with explicit `MetaData` naming conventions, SQLite `PRAGMA foreign_keys=ON` and `busy_timeout=5000`, and `render_as_batch=True` for SQLite; default blank `DATABASE_URL` in `Settings` to `sqlite:///<WORKSPACES_DIR>/engineering_agent.db` (resolving relative SQLite paths against `REPO_ROOT` while passing PostgreSQL URLs through unmodified); run `upgrade_database` during FastAPI lifespan startup and dispose the engine cleanly on shutdown; and name each project directory `<sanitized_stem>_<short_id>` (`NFC`-normalized Arabic/Latin stem stripping Windows-reserved names and forbidden characters, bounded below `MAX_PATH` and verified against path traversal), removing the directory if DB persistence fails.
- **Alternatives:** Requiring a separate async SQLite driver (`aiosqlite`), opaque UUID-only workspace folders on disk, or requiring manual CLI `alembic upgrade head` before `scripts/start.bat`.
- **Reason:** Synchronous SQLAlchemy/Alembic works deterministically on Windows with portable SQLite/PostgreSQL types, legible Arabic folder slugs remain easy to inspect in Explorer without collisions or invalid-path errors, and lifespan migration guarantees cold-start and restart persistence.

## ADR-009 — Step 03 File ingestion, read-only originals, versioning, and schema constraints (Step 03)
- **Context:** Step 03 requires safe multi-file upload, extension-based folder classification, SHA-256 integrity hashing, read-only originals, duplicate detection, non-overwriting versioning, download endpoints, path-traversal/size guards, and audit logging, plus stricter DB safeguards before Step 03 feature work (`ON DELETE RESTRICT` on `files.project_id` and `file_versions.file_id`, `CHECK` constraints on `classification`, and documenting the project-creation `rmtree` rollback scope).
- **Decision:**
  1. Replace `ondelete="CASCADE"` with `ondelete="RESTRICT"` on `files.project_id` and `file_versions.file_id` (plus `passive_deletes="all"` and non-deleting ORM cascades) in migration `0002`, and enforce `CHECK` constraints across all five classified tables (`projects`, `files`, `tasks`, `deliverables`, `calculations`) for the exact five `CLAUDE.md` labels (`Preliminary`, `Conceptual`, `For Review`, `For Coordination`, `For Approval`) in migration `0003`; disable SQLite `PRAGMA foreign_keys` during batch table rebuilds in `alembic/env.py` followed by `PRAGMA foreign_key_check`.
  2. Enforce a 41-extension allowlist matching `docs/SPEC.md` §6A (`01_Input_Documents` vs `02_Original_Drawings`), reject path traversal, drive prefixes, reserved Windows stems, NUL bytes, empty files, and oversized streams (`MAX_UPLOAD_SIZE_BYTES = 50 MiB` default, `MAX_FILES_PER_UPLOAD = 25`) atomically before disk commit, and use `python-multipart==0.0.34`.
  3. Store initial `v1` uploads with `0o444` (`FILE_ATTRIBUTE_READONLY` on Windows) in their classified folder, match existing filenames case-insensitively on Windows NTFS to detect unchanged SHA-256 duplicates vs changed updates, write `v2+` versions into `12_Revision_History/<file_id>/v<N>_<filename>` (`0o444`) leaving `v1` untouched, and block `PUT`/`PATCH`/`DELETE` requests on tracked files with HTTP `403`.
- **Alternatives:** Allowing API file replacement in place, relying only on Pydantic validation without database `CHECK`/`RESTRICT` constraints, or storing revisions inside `01_Input_Documents` with renamed suffixes.
- **Reason:** Combining database constraints, OS read-only file permissions, HTTP `403` immutability guards, and isolated `12_Revision_History` versioning ensures originals can never be silently overwritten or orphaned on Windows.

## ADR-010 — Step 04 Swappable LLMProvider, Gemini SDK, and Keyring Secret Storage (Step 04)
- **Context:** Step 04 requires a swappable `LLMProvider` abstraction supporting text, structured JSON output, PDF/image multimodal inputs, tool calling, and token/usage logging, plus a `GeminiProvider` using the official Google GenAI SDK, a Settings page storing API credentials strictly in the OS credential vault (never returned by API endpoints, never stored in `.env`, SQLite, logs, or git), model selection per complexity (`fast` vs `deep`), and daily usage caps.
- **Decision:**
  1. Address PR #9 hardening first: intercept `POST /api/projects/{id}/files` `Content-Length > MAX_FILES_PER_UPLOAD * MAX_UPLOAD_SIZE_BYTES` via pure ASGI `UploadSizeLimitMiddleware` before Starlette parses multipart bodies (while chunked uploads without `Content-Length` remain protected by the per-file streaming limit), map `FileExistsError` -> `409` and explicit domain exceptions (`EmptyFileError`, `TooManyFilesError`, `UnsafeFilenameError`, `UnsupportedFileTypeError`, `WorkspacePathError`) -> `400` in `api/files.py`, enforce allowlist `mime_hint` on storage and download, and reject `..` only as a whole path segment so filenames like `Plan Rev..A.pdf` succeed.
  2. Define provider-agnostic `LLMProvider` (`backend/app/providers/base.py`), `GeminiProvider` (`backend/app/providers/gemini.py`) using `google-genai==3.6.1` (`gemini-3.8-flash` fast default, `gemini-4-argon` deep default, `gemini-3.5-flash-lite` in fallback catalog, plus manual model-ID override) and `create_provider` registry (`backend/app/providers/registry.py`). Because owner live verification hit `404 NOT_FOUND` on retired `models/gemini-2.5-flash`, add SDK `models.list()` discovery filtered to `generateContent` (`POST /api/settings/provider/models/refresh` and best-effort `refresh_models_on_startup`) alongside a clear `ProviderModelNotFoundError` (`400`) naming the configured model and pointing to the refreshed list.
  3. Store the API key exclusively in Windows Credential Manager (`WinVaultKeyring` via `keyring==25.7.0`, service `"ai-engineering-agent"`, account `"gemini_api_key"`), expose only `api_key_configured: bool` and `credential_backend` over HTTP (`GET/PUT/DELETE /api/settings/provider*`), and enforce `sanitize_secret_text` redaction across exceptions and logs.
  4. Persist non-secret model preferences and both **daily and monthly** caps (`daily_request_limit`, `daily_token_limit`, `monthly_request_limit`, `monthly_token_limit`, `max_output_tokens`) in `settings`, record all remote provider attempts (both successful calls and failed calls that reached Google, including reported tokens) as **append-only rows** (`entity_type="provider_usage"`) in `audit_log` and sum them cleanly to avoid read-modify-write counter races, enforce daily and monthly caps in `_check_usage_budget` before calls, and provide `scripts/verify_gemini_live.py` for owner-local live checks via `keyring`.
- **Alternatives:** Using the legacy `google-generativeai` package, storing encrypted keys in SQLite/`.env`, or returning masked key suffixes in API JSON.
- **Reason:** `google-genai` is Google's current official SDK supporting native structured `response_schema`, `Part.from_bytes` PDF/image inputs, tool declarations, and `usage_metadata`; OS keyring storage plus boolean-only status eliminates key leakage paths completely.

## ADR-011 — Provider 503 Exponential Backoff Retry & Step 05 Orchestrator v0 / Task Engine (Step 05)
- **Context:** During owner live Gemini verification, `gemini-4-argon` raised transient `HTTP 503 UNAVAILABLE` high-demand errors. Step 05 also requires a natural-language "New Assignment" engine backed by Orchestrator v0 (restate assignment, identify discipline/deliverables/files/candidate standards to verify/missing info/assumptions, ask clarifying questions only if missing info materially affects the result, store structured JSON, log failures without hiding them, and show Task History).
- **Decision:**
  1. Add `ProviderServiceUnavailableError` (mapped to HTTP `503` in `api/settings.py`) and wrap SDK calls in `GeminiProvider._call_with_503_retry` across both `generate()` and `list_models()` using short exponential backoff (`max 3 tries`, delays `0.5s`, `1.0s` — injectable via `sleep_fn` for deterministic tests) while preserving 1 logical request count in the usage ledger.
  2. Keep Step 04 completion records authoritative by updating `docs/reports/step-04.md` to `COMPLETE` with the owner's sanitized live verification metrics (`WinVaultKeyring`, `gemini-3.5-flash-lite`, `27` discovered `generateContent` models, structured JSON, PDF span check, image color check).
  3. Add Alembic migration `0004_step05_task_metadata` adding nullable `complexity`, `provider_name`, `model_name`, `attached_file_ids_json`, `structured_output_json`, and `token_usage_json` columns on `tasks` while preserving `ck_tasks_classification_valid` and Step 03 `RESTRICT` constraints.
  4. Implement Orchestrator v0 (`backend/app/agents/orchestrator.py`) using `OrchestratorUnderstanding` structured JSON schema, JSON-encoded `<UNTRUSTED_PROJECT_METADATA>` / `<UNTRUSTED_ATTACHED_FILES>` / `<UNTRUSTED_ASSIGNMENT_INPUT>` blocks escaping `<` / `>` as `\u003c` / `\u003e` across every untrusted field (`prompt`, project metadata, filenames), strict anti-fabrication rules in `restated_assignment`, deterministic enforcement that missing referenced files (`status == "missing"`) force `clarification_needed = True` with targeted questions, and `suggested_classification` strictly advisory so the owner's chosen `Task.classification` is never overwritten.
  5. Persist every task run (`Task`, `TaskStep` #1 `assignment_intake`, `TaskStep` #2 `orchestrator_v0`, and `AuditLog` entries `task.created`, `provider.usage_*`, `task.completed` / `task.failed`) via `POST /api/tasks`, `GET /api/tasks`, and `GET /api/tasks/{task_id}`, filtering `provider_usage` rows by `task_id` directly in SQL (`AuditLog.details_json["task_id"].as_string()`). At server startup, `mark_stale_running_tasks_interrupted` marks any orphaned `"running"` tasks/steps from a crash or restart as `"failed"` (`interrupted`). When provider calls fail cleanly (`401`/`404`/`429`/`503`/missing key/bad JSON), commit `status="failed"` with sanitized `error_message` and return the failed `TaskDetailOut` (rendered prominently in UI `.status-box.status-err`) so failures are never hidden.
- **Alternatives:** Retrying `503` inside `execute_provider_request` (which would multiply usage-counter increments), hiding failed runs behind rollback-only `500` responses, or omitting Alembic columns and storing structured output solely inside `TaskStep.output_payload`.
- **Reason:** Provider-layer retry shields callers cleanly with single-request usage accounting; dedicated nullable `Task` columns + step/audit history enable fast filtered Task History queries and complete observability of errors and token usage.

## ADR-012 — Orchestrator Assumption Labelling & Step 06 Deterministic File Extraction Layer (Step 06)
- **Context:** Step 05 review feedback identified that unstated engineering parameters (such as beam support boundary conditions) must never be phrased as established facts; every assumption must be explicitly labelled as an unverified assumption to confirm with the owner. Step 06 also requires deterministic, non-AI extraction across PDF (text, tables, page PNGs, `ara+eng` OCR fallback), DOCX, XLSX (formulas + cached values), CSV, PPTX, and raster images preserving exact numbers/units and read-only originals while cleanly detecting and reporting absent Tesseract (`not installed - pending owner`).
- **Decision:**
  1. Tighten `ORCHESTRATOR_V0_SYSTEM_PROMPT` (`backend/app/agents/orchestrator.py`) and enforce prefix-only matching (`startswith`) inside `_normalize_assumptions()` so every unprefixed assumption is prefixed (`"Assumption (to confirm with owner): ..."` / `"افتراض أولي يحتاج تأكيد المالك: ..."`), preventing mid-sentence phrases from suppressing owner-confirmation labelling.
  2. Install and pin Step 06 Python extraction libraries (`pymupdf==2.1`, `pdfplumber==0.11.10`, `python-docx==1.2.0`, `openpyxl==3.1.5`, `python-pptx==1.0.2`, `pillow==13.0.0`, `pytesseract==0.3.13`) in `backend/requirements.txt`, without auto-installing OS binaries.
  3. Implement single-probe runtime Tesseract detection (`probe_tesseract` / `detect_tesseract` probing `TESSERACT_CMD`, `PATH`, and default Windows install directories once per run) returning `'not installed - pending owner'` cleanly when absent (with de-duplicated per-run warnings), and dedicated `300 DPI` separate OCR rendering in `extract_pdf` (`PDF_PREVIEW_DPI = 150` previews vs `PDF_OCR_RENDER_DPI = 300` OCR pass, recorded as `ocr_dpi` in JSON/API output).
  4. Use `csv.reader(io.StringIO(text, newline=""))` for CSV extraction, call `ws.reset_dimensions()` with `_SafeExcelReader` (`openpyxl` chartsheet crash fix), track exact 1-based `row_numbers`, `start_row`, `start_column`, `start_column_letter`, and keep `raw_text` / `raw_uncollapsed_values` + `normalization_applied` alongside whitespace-normalized text/tables.
  5. Persist normalized extraction payloads (`ExtractedItem` anchored to `source_file`, `page_or_sheet`, and `location`) both in `file_extractions` (`0005_step06_file_extractions` Alembic migration) and in fresh non-overwritable `03_Analysis/extractions/<file_id>/v<ver>/r<run_num>/` directories (refusing HTTP `409` if `r<run_num>` already exists), checking `sha256_after == sha256_before` before commit and persisting failed `FileExtraction` + `file.extraction_failed` `AuditLog` records on hash mismatch.
- **Alternatives:** Sending binary documents directly to Gemini for extraction (violates Step 06 deterministic goal and risks fabricated/rounded quantities), overwriting one `extraction.json` per file, or crashing when Tesseract is absent.
- **Reason:** Deterministic parsing (`pymupdf`, `pdfplumber`, `openpyxl` dual formula/value read, `python-docx`, `python-pptx`, `Pillow`, `pytesseract`) guarantees exact verbatim numbers, trailing decimals, and coordinates with full provenance and zero mutation of originals.

## ADR-013 — CAD (DXF, DWG via ODA File Converter), BIM (IFC), and Opt-In Gemini Vision Drawing Summary (Step 07)
- **Context:** Step 07 requires deterministic ingestion of vector drawings (`.dxf`), binary Autodesk drawings (`.dwg`) converted through an external ODA File Converter installation without altering read-only originals, BIM models (`.ifc`), opt-in AI visual summarization of rendered drawing PNGs strictly labelled as non-measurement, and an honest Native / Converted / Not Supported format matrix.
- **Decision:**
  1. Pin `ezdxf==1.4.5` and `ifcopenshell==0.9.0.post1` in `backend/requirements.txt` (using already-installed `pymupdf==2.1` via `ezdxf.addons.drawing.pymupdf.PyMuPdfBackend` for white-background A4 PNG ModelSpace rendering), without auto-installing OS software or claiming native binary DWG/RVT support.
  2. Add `Settings.oda_file_converter_path` (`ODA_FILE_CONVERTER_PATH`) in `backend/app/core/config.py` and probe ODA in strict precedence (`ODA_FILE_CONVERTER_PATH` -> `PATH` -> standard Program Files `ODA/ODAFileConverter*/ODAFileConverter.exe`) once per extraction run via `probe_oda()` / `detect_oda()`. When absent, report `"not installed - pending owner"` proactively in `/api/extraction/capabilities` and fail `.dwg` extractions cleanly (`422` + persisted `FileExtraction(status="failed")` + `file.extraction_failed` `audit_log`).
  3. Keep original `.dwg` files strictly read-only: stage ONLY target `.dwg` bytes in an isolated temporary input directory for `ODAFileConverter`, write converted `ACAD2018` `.dxf` into fresh non-overwritable `03_Analysis/extractions/<file_id>/v<ver>/r<run_num>/converted/` (refusing HTTP `409 Conflict` if `r<run_num>` or `r<run_num>/converted` already exists on disk), check `sha256_after == sha256_before` on the original, and run `extract_dxf(..., extraction_method="converted_oda")`.
  4. Extract DXF header `$INSUNITS` verbatim (without converting `$INSUNITS=0` unitless areas to `m2`), Arabic/English layer names, block definitions + XREF flags (`block.is_xref` / `xref_path`), `TEXT`/`MTEXT`/`ATTRIB`, `DIMENSION` measurements + overrides, closed polyline/circle areas, net `HATCH` areas (`ezdxf.path.nesting.make_polygon_structure` + `hatch_style` subtracting island cutout holes from outer boundaries cleanly and recording `gross_area_native`, `island_hole_area_native`, `island_count`, and `area_basis`), and ModelSpace vs PaperSpace counts; extract IFC units, storeys, `IfcSpace` (leaving unauthored areas `null`), `IfcWall`, `IfcDoor`, `IfcWindow`, `Pset_*`, and `Qto_*` via `ifcopenshell`.
  5. Add `POST /api/extractions/{extraction_id}/vision-summary` routing rendered page PNGs through `execute_provider_request`, enforcing `ai_interpretation_only=True` and a mandatory non-measurement disclaimer, saving immutable `vision_page_<N>_s<k>.json` artifacts in `03_Analysis`, and rendering the Drawing & BIM Inventory Table + Format Support Matrix in `ProjectFilesPanel.tsx`.
- **Alternatives:** Claiming partial binary DWG heuristics without ODA, computing implicit unauthored IFC space areas from meshes, auto-running vision LLM calls inside deterministic file extraction, or passing `02_Original_Drawings/` directly to `ODAFileConverter`.
- **Reason:** Staging `.dwg` conversions inside isolated run directories protects originals and multi-file workspaces; explicit tool detection, honest unit/XREF/3D limits, and strict separation between deterministic geometry metrics and AI visual summaries prevent engineering hallucination.

## ADR-014 — CAD Unit Plausibility Verification, Owner Unit Override, and CP1256 Arabic Recovery (Step 07b)
- **Context:** Real-world `.dwg` testing exposed two production defects: (1) drawings declaring `$INSUNITS=1` (inches) while drafted in metric units produced metric areas off by ~`1550x` (`1 / 0.0254²`), and (2) legacy Windows ANSI `cp1256` Arabic strings (such as `'ÔÌÑÉ ãáæäÉ'`) arrived Latin-1/CP1252-decoded as mojibake after DWG-to-DXF conversion. Additionally, HATCH net area reporting required renaming `island_hole_area_native` to `net_subtracted_area_native`.
- **Decision:**
  1. Run `_assess_cad_unit_plausibility()` across `DIMENSION` measurements, `DIMENSION` overrides, and closed polyline/circle/hatch areas & perimeters before emitting `area_m2`. Whenever `$INSUNITS == 0` or declared units conflict with drawing dimensions/geometry (unless explicitly confirmed by the owner), set `units_doubtful = True`, set `area_m2 = None` (`null` in JSON) everywhere, keep `area_native` and `area_native_unit` untouched, and emit `"units doubtful - owner must confirm drawing unit"`.
  2. Support explicit per-extraction owner confirmation (`confirmed_unit` in `POST /api/files/{file_id}/extract` and `POST /api/extractions/{extraction_id}/confirm-unit`) persisting immutable `unit_confirmation_s<k>.json` artifacts and `file.drawing_unit_confirmed` audit entries while keeping raw native geometry and SHA-256 hashes unchanged.
  3. ## ADR-015 — Analytical LWPOLYLINE Bulge Area, Confirmed Display Units, and Step 08 Controlled Internet Research (Step 08)
- **Context:** PR #14 owner review requested (1) a synthetic hand-calculated closed `LWPOLYLINE` arc-bulge test (`LWPolyline.flattening` did not exist in `ezdxf==1.4.5` and had previously failed silently for curved segments) and (2) displaying confirmed units (`sq m` / `m`) cleanly while retaining untouched raw declared values (`sq_in` / `in`). Step 08 introduces controlled internet research respecting Step 04 usage limits, prioritizing reliable sources (`official_regulations` -> `standards_bodies` -> `government` -> `manufacturer` -> `peer_reviewed` -> `reputable`), rejecting search snippets as evidence, isolating fetched pages as untrusted data, and marking inaccessible documents `unreviewed`.
- **Decision:**
  1. Replace invalid `.flattening()` calls on `LWPOLYLINE` with analytical circular-segment math (`_polyline_bulge_area_and_perimeter`) over `(x, y, bulge)` vertices, shared across both `LWPOLYLINE` and 2D `POLYLINE`, achieving exact agreement with hand-calculated semicircular/concave geometries (`30.283185` and `17.716815 m2`).
  2. Emit `display_area`, `display_area_unit` (`sq m`, etc.), `display_perimeter`, `display_perimeter_unit` (`m`, etc.), and `raw_declared_unit` alongside untouched `area_native`, `area_native_unit`, and `perimeter_native` after owner unit confirmation, rendering both clearly in `ProjectFilesPanel.tsx`.
  3. Default controlled web search (approved by owner) to free zero-key **`duckduckgo_lite`** (explicitly best-effort, recommending optional free **Tavily** key in Settings first on rate-limit/anti-bot challenge) + scholarly **`crossref`**, with pluggable optional keyring-backed adapters (`tavily`, `serper`, `brave`) ready without locking into a paid search vendor. Discard all search-engine snippets before evidence synthesis; validate every URL against SSRF (`validate_public_http_url`); fetch HTML (`lxml.html`, active tags & comments stripped) and PDF (`pymupdf`) using a transparent app User-Agent (`LocalAIEngineeringAgent/0.8`) with a single Referer-less minimal-header retry on `403`/`406`/`429`; mark persistent HTTP errors/paywalls/CAPTCHAs/timeouts strictly as `inaccessible` + `reviewed=False` + `reliability_assessment="unreviewed"` (`"unranked"` in UI, guiding owner to download & upload in Projects & Files); support attaching uploaded project files directly as `owner_provided` (`reviewed=True`, owner-chosen priority tier); skip Gemini synthesis cleanly (`0` tokens, `status="no_accessible_sources"`) whenever zero sources are reviewed; wrap all fetched text inside `<UNTRUSTED_WEB_PAGE_CONTENT>` via `_encode_untrusted_json_block()`; route optional AI synthesis through `execute_provider_request()` honoring Step 04 usage caps; and persist `ResearchRun` (`0006_step08_research_runs`), `ResearchSource`, `11_References/research/<run_id>/research_log.json`, and an RTL/LTR `ResearchView` UI tab.
